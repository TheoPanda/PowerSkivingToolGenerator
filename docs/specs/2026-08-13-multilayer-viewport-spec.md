# 3D 视口多图层基础设施（子 PRD-1）实现 Spec

**日期**：2026-08-13
**父 PRD**：`../prds/2026-08-13-envelope-calculation-prd.md` → `envelope/01-multilayer-viewport.md`
**状态**：待实现
**来源**：grilling 访谈（Q1–Q12 全 A）+ 前后端代码调研

## Problem Statement

步骤2「包络计算」当前只能显示一个工件齿轮——3D 视口是「单模型替换」语义，模块② 要逐步展示的扫掠点云 / 前刀面 / 刃形 / 后刀面 / 单齿模型**无法叠加**在同一视口；后端导出器也只支持实体三角网格，**无法导出**曲面片、空间曲线、点云。要落地模块② 的「分阶段叠加可视化」，必须先补一块地基：多图层视口 + 图层开关交互 + 非实体导出。

## Solution

把 3D 视口从「单模型替换」重构为「命名图层集」，支持增量叠加、显隐、透明度、聚焦；在画布右侧提供一个**正式**的图层列表交互；后端新增泛化的非实体 GLB 导出。本子 PRD 用占位假数据验证整套交互，不实现任何包络算法（K-2.x 留后续子 PRD）。

## User Stories

1. 作为车齿刀设计人员，我希望工件齿轮在视口中作为「参考基准图层」常驻，而不是被后续几何体替换掉。
2. 作为车齿刀设计人员，我希望每个包络阶段算完后，新几何体**叠加**到视口上（而非覆盖），从而看见「刀具几何如何一步步诞生」。
3. 作为车齿刀设计人员，我希望有一个图层列表，能**单独开关**每一个几何体——只亮「扫掠点云」就只看扫掠点云，只亮「刃形」就只看刀刃。
4. 作为车齿刀设计人员，我希望图层列表有一键「全部显示」，回到「所有几何体叠加在一起」的样子。
5. 作为车齿刀设计人员，我希望**点某个图层名**时，其余图层变淡、相机平滑转到该图层中心，让我聚焦看它。
6. 作为车齿刀设计人员，我希望每个图层能**调透明度**，半透明曲面不遮挡后面的几何。
7. 作为车齿刀设计人员，我希望工件齿轮既有的生成与展示流程（步骤1 填参数 → 步骤2 生成 → 结果面板唤出）**完全不受影响**。
8. 作为开发者，我希望后端能导出**空间曲线 / 点云 / 曲面片**的 GLB，而不只是实体。
9. 作为开发者，我希望多图层反复增删后 `dispose` 不残留 GPU 资源（不泄漏）。
10. 作为开发者，我希望图层配色 / 材质定义集中在**一处**，改一个颜色不用到处找。

## Implementation Decisions

### 渲染架构：分阶段独立 GLB + 增量叠加
- 每个包络阶段的后端端点返回**本阶段一个几何体的独立 GLB**；前端按图层 id **增量 `addLayer`** 叠加，工件齿轮作为 `workpiece` 层先加载、其余层叠加其上。
- 前端图层 API 以 **`addLayer(layer)` 为主入口**；`loadLayers(layers[])` 只是内部循环 `addLayer` 的批量便捷层。
- `loadGear` 降级为「清空非工件层 + 加载 / 刷新工件层」的薄适配，保证既有调用方零改动。
- GLB 的 `node.name` 写入图层 id，但**仅作调试 / 缓存恢复标签**；前端识别图层靠 `addLayer` 显式传入的 id，不解析 `node.name`。

### 图层数据送达视口
- 新增一个 window 事件 `gear:layer-ready`（detail 携带图层 id + glbBase64），与既有 `gear:model-ready` 并列；视口同时监听两者，前者走 `addLayer`、后者仍走 `loadGear`。

### 图层模型（契约）
- 图层 id 集合：`workpiece | swept_cloud | rake | edge | flank | singleTooth`。
- 图层规格承载：id、几何种类（`mesh | line | points`）、glbBase64、默认透明度、材质预设（`steel | carbide | swept_cloud | rake | edge`）、是否 `doubleSide`。

### 配色 / 材质单源
- 材质颜色 + PBR 参数全部收敛到**一个纯数据模块**（`layerPalette`）；与全局主题里同名色（品牌蓝 `#0060A0`、冰蓝 `#E8F0F8`、深色 `#1f2937`）用注释互相指路，**不做运行时联动**。
- 每层材质 `material.clone()` 独立实例，防止调一层透明度串改其它层。

### 图层交互（正式功能）
- 画布右侧浮一个图层列表：每行 = 色块 + 名称 + 眼睛开关（显隐）+ 透明度滑条 + 聚焦。
- 顶部「全部显示」按钮一键回到叠加。
- 聚焦 = 其余层 opacity 降至 0.12 + 相机向该层包围盒中心插值 500ms（品牌缓动）。
- 本子 PRD 用**占位假数据**（一个半透明片、一条线、几个点）顶着未来图层的坑位，验证交互；接真数据时只换形状不换交互。

### 后端非实体导出
- 新增一个泛化导出函数，输入「几何体列表」（每项区分 `mesh / line / points` + 顶点数组 + 可选图层 id），输出 GLB；`node.name` 写图层 id。
- 曲线导出为 `LINE_STRIP`（有序顶点）；点云导出为 `POINTS`；曲面片导出为三角网格 `TRIANGLES`（`doubleSide`）。
- 落点在**共享层**（与既有工件导出器并列），不改动既有实体导出路径。

### 资源清理（dispose 收尾）
- 补上既有的清理遗漏：PBR 材质、环境贴图、画布 DOM 一并释放；多图层增删后 `dispose` 无残留 geometry / material。

### 测试接缝
- 视口的渲染器创建做成**可注入**，使图层逻辑（增删 / 显隐 / 透明度 / 聚焦 / dispose）能在无真实 WebGL 上下文的环境里测试。

## Testing Decisions

- **纯逻辑层**：图层 id 集合、图层规格类型、配色 / 材质常量——直接单测（不依赖 Three.js）。
- **视口图层逻辑**：注入假渲染器后，测「addLayer 后场景含 N 个独立 group」「显隐正确」「调透明度不串改其它层（材质 clone）」「dispose 无残留」。
- **后端导出**：测导出的 GLB 其 primitive `mode` 字段正确（曲线 = 线条、点 = 点、曲面 = 三角形），`node.name` 写图层 id。
- **零回归门禁**：既有前端测试全绿；工件齿轮生成流程（工件 GLB → 视口 → 结果面板）不变。
- **测试边界**：只测外部行为（图层接口 + 导出契约），不测渲染像素；符合项目「测 provide/inject 接口、不测 DOM 细节」的既有边界。
- **分层约定**：沿用既有「纯数学单测 + OCCT 集成测试」的 docstring 区分，不引入新的 pytest 标记；回归基准沿用「硬编码 golden 常量」模式。

## Out of Scope

- 任何包络算法（K-2.x）：前刀面、扫掠点云、刃形、后刀面、单齿的**真实计算**。
- 真实包络数据接入（本子 PRD 用占位假数据）。
- 解析路线（K-2.6~2.8）与双路线互检。
- 图层列表位置持久化到 localStorage（可后续加，不在本子 PRD 必做项）。
- 斜齿（β_w≠0）包络（MVP 禁用，见父 PRD）。

## Further Notes

- 权威源对齐：坐标标签随数据传递（各几何在刀具动系 T）；内部 mm / rad、接口 ° / r/min；模型传输仅 glTF/GLB。
- 缺口纪律：本子 PRD 不触碰任何未销项公式；Three.js `linewidth` 在 WebGL2 被忽略，刃形曲线若发虚，后续子 PRD 以 ribbon（法向细带）兜底。
- 上游依赖：非实体导出能力是后续所有子 PRD（扫掠点云 / 刃形 / 后刀面可视化）的前置，本子 PRD 只交付能力与交互，不交付几何。
