## 1. 概述

**用户故事**：作为车齿刀设计人员，我希望在输入工件齿轮与刀具参数后，系统能**逐步**展示刀具几何体（产形面 → 前刀面 → 刃形 → 后刀面 → 单齿模型）是如何通过「反向包络」一步步诞生的，并在每一步都能看到可验证的中间几何、量化诊断指标与可操作的失败升级路径，从而把「刀具设计」从一次黑盒计算变成一段可理解、可校对、可干预的过程。

**一句话**：把设计书模块②「反向包络」从「一次算完扔出结果」升级为「分阶段计算 + 分阶段叠加可视化」的流水线体验。

## 2. 术语澄清（重要，先对齐）

用户原表述「铲形面」经确认为「**产形面**」（GeneratrixSurface，共轭面/生成面）笔误（拼音 chǎn xíng miàn 相同）。本文档全文统一采用设计书术语「产形面」，下表仅作更正对照：

| 用户表述 | 设计书术语 | 英文 | 归属模块 | 定义 |
|---|---|---|---|---|
| 铲形面 | **产形面** | GeneratrixSurface | ②b 输出 | 由工件齿面经共轭/包络生成的刀具侧生成面（解析为 K-2.6 参数化曲面；离散为扫掠点云 ⋃cloud_j） |
| 前刀面 | 前刀面 | RakeSurface | ②a 输出 | 独立设计输入（非共轭派生物），隐式方程 F(x,y,z)=0 + 法矢场 |
| 后刀面 | 后刀面 | FlankSurface | ②c 输出 | 刃形 + let-off（铲形/重磨）运动扫掠所得，=「重磨后刀刃的集合」 |
| （用户未列，但为关键中间对象） | **刃形** | EdgeCurve | ②b 输出 | 空间曲线 = 产形面 ∩ 前刀面，即切削刃 |

设计书 §4.3.2 已明确规划「三维过程可视化：工件齿轮 / 产形面 / 前刀面 / 刃形 / 后刀面逐步展示」（00_大纲决策 8），本功能正是把这条已定契约落地。

**结论：现有计算不支持包络计算，但基础已铺好，缺失面清晰，可按分阶段补齐。**

### 3.2 缺失清单（模块② 需要、尚未实现）

| 缺失 | K 编号 | 说明 |
|---|---|---|

### 3.3 结论

后端 `backend/core/envelope/`（模块②）与 `backend/core/solid/`（模块③）目录当前**不存在**（CONTEXT.md 标注「待建」）。前端 `loadGear` 是「单模型替换」语义，无法叠加展示多个几何体。因此本功能需**同时新建后端包络计算模块 + 重构前端 3D 视口为多图层系统**，两者缺一不可。

## 4. 功能目标与范围

### 4.1 目标

1. **分阶段反向包络**：②a 前刀面 → ②b 产形面/刃形 → ②c 后刀面 → 单齿预览，逐步计算、逐步可视化。
2. **多图层叠加视口**：6 个语义图层（工件齿轮 / 产形面 / 前刀面 / 刃形 / 后刀面 / 单齿）独立开关、透明度、聚焦。
3. **可干预的诊断**：每阶段展示量化指标（ffα、覆盖判据、收敛计数、拟合残差），失败时给出映射设计书失效表的可操作升级路径。

### 4.2 范围界定（MVP）

- **做**：圆柱刀 + 平面前刀面（K-2.3 通用方程为主，K-2.1 平面为锚点）+ 离散包络路线（②b）+ 分截面包络后刀面（②c）。
- **二期**：解析共轭路线（②b analytic）+ 双路线一致性互检（§5.5）。
- **缓行**（未销项禁区，见 §10）：锥面刀变位族（K-2.14）、多刃刀（T7）、机床补偿（K-2.26/27）、工作角度校核（K-2.20~22）。
- **斜齿（β_w≠0）**：MVP 显式禁用（T2 s_d 判定表 / W1 Σ 符号未销项），界面灰置 β_w 输入并提示「斜齿工件包络待后续版本」，日后开发。
- **单齿模型**：作为模块③ 的「预览节点」，显式标注 source=模块③ 预览、非②交付实体。

## 5. UX 交互设计（问题二：极佳 UX 的交互过程）

### 5.1 核心设计主张

**「分阶段计算 + 分阶段叠加可视化」** —— 让用户**看见刀具几何如何从包络中一步步诞生**，而非等一次黑盒计算后抛出成品。

> 依据设计书 §1.1「数学做设计，仿真做验证」：模块② 是自包含数学内核，每个子阶段产出一个可验证的中间几何，天然适合逐步揭示。

### 5.2 信息架构：步骤2 内做「流水线子步骤」

**决策**：保持 5 步导航不变，在**步骤2「包络计算」内部**新增纵向「子阶段步进器」，而非把 5 步拆成 7~8 步。

- **理由**：5 步是「模块级」语义（①工件→②包络→③几何→④仿真→⑤工艺），与设计书六模块对齐；2a/2b/2c 有强制前后依赖（刃形 = 产形面∩前刀面 K-2.8；后刀面 = 刃形+let-off K-2.19），是「一个模块内的一趟串行计算」，拆分反而暗示可跳转，误导用户。
- **副作用修正**：当前步骤2 标签已是「包络计算」却挂载 `WorkpieceViewer`（模块① 占位）。本功能将**模块① 的工件齿轮 GLB 降级为视口常驻「参考基准图层」**，步骤2 正式承载模块②。

```
5 步导航（不变）
  ① 待加工齿轮    ✅
  ② 包络计算      ← 本次：内部子阶段流水线
  ③ 刀具几何体    待定（模块③ 正式交付）
  ④ 仿真验证      待定
  ⑤ 工艺文件      待定
```

**步骤2 内部子阶段流水线**（5 个子阶段，纵向）：

```
2a 前刀面      ──►  RakeSurface（前刀面半透明平面）
2b.1 产形面    ──►  GeneratrixSurface（共轭生成面，品牌蓝半透明）
2b.2 刃形      ──►  EdgeCurve（高亮空间曲线，逐点生长）
2c 后刀面      ──►  FlankSurface（重磨刃形族拟合面）
单齿预览       ──►  前刀面+后刀面+刃形闭合成单齿（标注=模块③预览）
```

> 2b 拆成两个产物，因 §4.3.2 契约同时输出 GeneratrixSurface 与 EdgeCurve，且用户明确要求先看产形面（共轭面）再看刃形。

### 5.3 状态机：阶段-状态-产物

每个子阶段四态：`pending`（灰）/ `running`（转圈蓝）/ `done`（对勾绿）/ `failed`（红叉）。

- 当前阶段 `running` 时其余 `pending` 禁用点击（防跳段）。
- `done` 的阶段可点击回看（隐藏后阶段图层、聚焦该阶段产物）。
- `failed` 阶段卡内列出「现象/检测/处理」三行摘要（直接映射设计书 §4.3.6 失效表），末行给「可执行修复」按钮。

### 5.4 主交互流

1. 用户完成步骤1 工件参数 → 工件齿轮 GLB 以**浅灰钢色**常驻视口（参考基准图层，半透明）。
2. 进入步骤2，填写刀具参数（组B：z_t/β_t/j_t/γ₀/α₀/tool_type/rake_type/L/n_L 等），点击**「开始包络计算」**。
3. 流水线逐阶段驱动：
   - ②a 算完 → 叠加**前刀面**（冰蓝半透明平面 + 法矢箭头）
   - ②b 算完 → 叠加**产形面**（品牌蓝 #0060A0 半透明，α≈0.35）→ 叠加**刃形**（高亮曲线，**逐点生长动画**对应 K-2.8 延拓法解点序列）
   - ②c 算完 → 叠加**后刀面**（硬质合金深灰）
   - 单齿预览 → 叠加**单齿模型**（硬质合金，标注 source=模块③ 预览）
4. 按钮文案随状态演变：「计算中…（当前子阶段名）」「失败重试 / 切换离散路线」。
5. 全部完成后，`ResultPanel` 追加「包络计算」结果区块（Σ、a、r_pt、ffα、刃形点数、产形面类型）。

### 5.5 图层控制面板

画布右侧浮一个图层列表（与「实体/线框」切换同区的看图工具，不占参数面板）：

| 图层 | 配色 | 透明度 | 说明 |
|---|---|---|---|
| 工件齿轮 | 浅灰钢 `steelMaterial` | 0.3（参考） | 模块①产物，常驻参考 |
| 产形面 | 品牌蓝 `#0060A0` | 0.35 | 共轭生成面，doubleSide |
| 前刀面 | 冰蓝 `#E8F0F8` | 0.45 | 半透明平面 |
| 刃形 | 深色 `#1f2937` 高亮 | 1.0 | LineSegments，renderOrder 最高，不参与 xray |
| 后刀面 | 硬质合金深灰 `carbideMaterial` | 0.6 | 半透明曲面片 |
| 单齿模型 | 硬质合金 `carbideMaterial` | 1.0 | 实心，source=模块③预览 |

每行：**色块 + 名称 + 眼睛开关（显隐）+ 透明度滑条 + 「聚焦」按钮**。

- **聚焦** = 隐藏其它五层、该层 opacity→默认值、camera 向该层包围盒中心插值过渡（500ms，品牌缓动）。
- 默认显隐：叠加到当前阶段的层显示，未算的层置灰禁用。
- 一键「全部显示」/「仅看刃形」。
- 图层状态持久化 localStorage。

### 5.6 诊断条（常驻，非弹窗）

步骤2 内容区底部常驻「诊断条」，展示当前阶段量化指标：

| 阶段 | 指标 | 阈值/上限 |
|---|---|---|
| ②b | ffα（双向包络复算 K-2.13） | < 0.1 μm |
| ②b | 覆盖判据（K-2.12） | 100%（每离散点对应一刀形点） |
| ②b | Newton 收敛计数 | N_max = 50 上限 |
| ②c | 截面拟合残差（K-2.18/19） | < 离散点间距一半 |

成功态显示绿色勾 + 数值；失败态展开**升级路径按钮**（映射设计书 §1.5 失效升级路径表）：

| 失效 | 升级路径（一键回填参数并重算对应阶段） |
|---|---|
| 解集发散 | 「切换离散路线」 |
| 刃形交叉 | 「调 γ₀/z_t/Σ 重算」 |
| 覆盖不足 | 「增大转角扫描区间」 |
| 刃形不连续 | 「加密离散 n」 |

> 用**内联诊断条 + 阶段卡徽标**而非弹窗，因模块② 是跨 ②/③ 的迭代回环（修正→回②b ≤5 次，§4.5），弹窗会打断迭代流。

### 5.7 视觉动效（渐进式揭示）

- 新图层叠加：opacity 0→目标值 + scale 0.92→1，280ms，品牌缓动 `cubic-bezier(0.22,0.61,0.36,1)`。
- 刃形「逐点生长」：`drawRange` 顶点 0→N，直观对应 K-2.8 延拓法解点序列，提升刃形连续性段的可读性。
- 所有过渡在现有 `animate()` 内逐帧逼近（与 `targetModelScale/targetOffsetX` 同模式），仅置 `sceneDirty`，无每帧开销。

### 5.8 认知引导

「反向包络」是抽象概念。UX 通过以下手段降低认知门槛：

1. **顺序即因果**：子阶段步进器的先后顺序本身就是「工件齿面 → 共轭产形面 → 前刀面 → 交线刃形 → 后刀面」的因果链，用户跟着顺序走即理解设计逻辑。
2. **产形面第一眼**：产形面（共轭面）作为第一步可验证产物，让用户先「看见共轭关系的存在」，再理解刃形是「交线」。
3. **坐标标签溯源**：图层 tooltip 标注坐标标签（T 系），呼应设计书 §1.4「坐标标签随数据传递」，让用户知道每个几何在哪个坐标系。

## 6. 数据契约

### 6.1 用户输入参数（对齐第3章参数字典）

| 组 | 参数 | 交互方式 | 默认/范围 |
|---|---|---|---|
| B 刀具 | `tool_type`（锥形/圆柱/多刃） | 必填 | 圆柱（MVP 仅圆柱可选，锥形/多刃灰置） |
| B | `z_t` 刀具齿数 | 必填 | 推荐区间 z_t/z_w≈0.5~0.67 |
| B | `β_t` 刀具螺旋角 | 必填 | 10~20° |
| B | `j_t` 刀具旋向 | 必填 | ±1 |
| B | `γ₀` 设计前角 | 可默认 | 5° |
| B | `α₀` 后角 | 可默认 | 6~8° |
| B | `rake_type` 前刀面形式 | 必填 | 平面 |
| B | `L` 总重磨量 | 必填（②c） | — |
| B | `n_L` 重磨等分数 | 可默认 | ≥5 |
| B | `δ` 轴倾斜角 | 可默认 | 0° |
| C 工艺 | `n_w`/`n_t` 转速 | 必填二选一 | 另一个按 K-1.8 导出 |
| C | `v_f` 进给 | 必填 | — |
| D 离散 | `n`=200、`m`=181、`NR`=200、`θ_range`=±20° | 可默认 | 第3章 §3.5 |

### 6.2 坐标标签与接口不变量（第2章 U 约定 + 第1章 §1.4）

- **坐标标签随数据传递**：点集/曲面必须携带所属系标签（W/T/F_w/F_t/R），无标签视为非法。模块② 各面均在刀具动系 **T** 中表达。
- **单位制**：内部 mm + rad；界面 °/r/min（U12）。
- **旋向二元表示**：β≥0 + j∈{+1,−1}，禁止负角（U7）。
- **解析/离散对偶**：②b 两路线输出同一 `EdgeCurve`，下游不感知路线差异（§1.4-4）。
- **溯源字段**：所有导出量带 source 标记（[N]/推导），供测试与审计。

### 6.3 模块② 输出契约（§1.3）

```
②a  RakeSurface  { F(x,y,z)=0, n_rake }                      坐标 T
②b  EdgeCurve    { pts[](有序), param_range, continuity, coverage_report }
    GeneratrixSurface { 参数化曲面 | 扫掠点云 }               坐标 T
②c  FlankSurface { section_edges[], flank_fit, resharpen_schedule a_i[] }
```

> **关键新增**：②b 契约必须**透传「刃形有序点序列 + 连续性标记」**（§4.3.2 `EdgeCurve.pts[]` 有序），否则前端「逐点生长动画」无法落地。

## 7. 3D 渲染架构改造

`src/three/gearViewport.ts` 从「单模型替换」重构为「命名图层集（LayerSet）」：

| 新接口 | 职责 |
|---|---|
| `addLayer(layer)`（主入口） | 增量追加单层（id + glbBase64 + kind(mesh/line/points) + 样式；淡入 + 相机轻微 frame） |
| `loadLayers(layers[])` | 批量便捷层（内部循环 `addLayer`） |
| `removeLayer(id)` / `clearLayers()` | 删除/清空业务层（保留工件基准层） |
| `setLayerVisible(id, bool)` | 显隐 |
| `setLayerOpacity(id, v)` | 透明度 |
| `focusLayer(id)` | 聚焦单层（其它淡至 0.12 + 相机过渡） |

图层数据驱动：每阶段后端返回 GLB 后，由前端派发 window 事件 `gear:layer-ready`（payload 含图层 id + glbBase64 + kind + 样式），视口监听该事件后调 `addLayer`，与既有 `gear:model-ready` 并列。

- 新增 `src/three/layerPalette.ts`：LayerId 类型 + 配色/材质/命名常量（纯数据源，可单测；与 `theme.css` 同名色注释互指，非运行时联动）。
- `dispose()` 语义重构：保留工件基准层、只增删业务层，每层 material `.clone()` 防串改，避免 WebGL 泄漏（呼应架构审查 C3 遗留）。
- xray 模式：作用于全部 Mesh 层；**曲线层（刃形）不参与材质替换**，始终高亮（例外需文档化）。

### 后端 exporter 扩展

现有 exporter 只面向模块① 实体。需新增「曲面片 / 点云 / 空间曲线 → GLB」路径：

| 几何类型 | GLB 表示 |
|---|---|
| 开放曲面片（前刀面/后刀面/产形面） | 三角网格 + `doubleSide` + 半透明材质 |
| 空间曲线（刃形） | `LineSegments` / `LINE_STRIP`（需返回**有序**顶点） |
| 点云（离散产形面） | `Points`（可选，或直接三角化） |

多图层 GLB 的 `node.name` 写入 LayerId，但**仅作调试标签**；图层识别由前端 `addLayer` 显式传入的 id 驱动，不解析 `node.name`。

## 8. API 设计（分阶段端点）

现有 `POST /api/workpiece/generate` 是单段全量返回。本功能采用**分阶段独立端点**（已定，非 SSE 流式），让前端能「边算边叠加、失败及时止损」：

```
POST /api/envelope/rake          # ②a  → RakeSurface
POST /api/envelope/generatrix    # ②b.1 → GeneratrixSurface
POST /api/envelope/edge          # ②b.2 → EdgeCurve（有序点列 + 连续性标记）
POST /api/envelope/flank         # ②c  → FlankSurface
POST /api/envelope/single-tooth  # 预览 → 单齿 GLB
```

前端顺序驱动各端点；异步框架留待模块④ 真实需求时引入（与 ADR-004 精神一致）。

错误契约沿用 `{ "error": "描述", "code": 400 }`；模型传输仅 glTF/GLB。

**重构约束（硬性）**：`gearViewport` 多图层重构**不得破坏模块① 已交付成果**——工件齿轮 3D 生成（`loadGear` 路径、`WorkpieceViewer`、规格窗口）保持零回归，现有前端测试全绿；`loadGear` 作为 `addLayer` 的薄适配层保留。注：`gearViewport` 的唯一消费者是 `MainView.vue`（经 `gear:model-ready` 事件），`WorkpieceViewer.vue` 只 emit 事件、不碰视口，故「零改动」自然满足；**零回归门禁聚焦 `MainView`**。

## 13. 决策记录（2026-08-13 用户确认）

1. **分阶段返回方式**：采用**分阶段独立端点**（非 SSE 流式）；`gearViewport` 多图层重构**不得破坏模块① 已交付成果**（零回归）。
2. **单齿预览归属**：接受「②流程末尾越级展示模块③ 预览」，显式标注 source=模块③ 预览。
3. **双路线默认**：默认只跑 auto 推荐的单路线；双路线对拍作为可选高级项。
4. **斜齿（β_w≠0）**：MVP 显式禁用，日后开发。
